# labyrinth-agent-setup [--owner USER] [--agent NAME] [--owner-login]: give the engineering agent (Claude) its own account, so
# what it does can be told apart from what the owner does, and limit what it may do as root. Run as root; idempotent. Undo the
# rules with --remove.
#
#   * the account (default `claude-agent`, at most 26 characters): a normal user whose password is locked, so nobody can log
#     in as it with one;
#   * its rules account, `AGENT-rules` (claude-agent-rules): a system account with no home, no shell and a locked password,
#     that no rule lets anyone become. The agent's root rules are written for it, and the agent itself may run one program
#     as root: the recorder /usr/bin/labyrinth-agent-rec, which asks sudo whether the rules account may run the command,
#     runs it only then, and records the session (its input, output and errors) in /var/log/labyrinth-agent, which only root
#     may read (sudo labyrinth-agent-rec list, replay ID);
#   * /etc/sudoers.d/50-labyrinth-agent: the agent's rules allow ONE program as root without a password,
#     /usr/bin/labyrinth-agent (from the labyrinth-tools package; it was the Python script /usr/local/sbin/labyrinth-agent
#     until 2026-11-11), which checks every action (installing the ecosystem's own packages, official-repository packages but
#     no remote-access tools, the ecosystem's own services, reading the journal, Heimdall maintenance windows, Limbo test runs
#     (manifests root put in /var/lib/limbo/build-agent, made here root's own 0755, or /etc/limbo/validation), the rollback
#     tool's read-only commands, user-side desktop files). Anything broader (any pacman command, systemd-run, install
#     anywhere, the firewall) needs the owner to open a window with their password: `sudo labyrinth-agent-window HOURS` (its
#     list is written for the rules account too). Installing a package the agent built still runs that package's code as root:
#     the checks make root deliberate and visible, not impossible. Every use is logged by sudo (sudo-rs) in the journal under
#     the agent's name, with the command and the folder, the recorder writes a line at the start and the end of each session
#     (with the record's SHA-256), and labyrinth-agent writes each action to the journal for Heimdall;
#   * /etc/audit/rules.d/50-labyrinth-agent.rules: the kernel audit log keeps every program started in the agent's root
#     sessions (the recorder sets their login uid to the agent's; ausearch -k labyrinth-agent -i); auditd is enabled and the
#     rules loaded (augenrules --load);
#   * --owner-login: the owner's session reaches the agent account only after the owner has typed their password (once per
#     terminal, kept 12 hours), so a program running as the owner cannot use the agent's rights while they have not;
#   * Heimdall is told who may open a maintenance window (maintenance_actors in /etc/heimdall/config.json);
#   * /usr/local/bin/claude-sudo CMD...: shorthand for `sudo -n -u AGENT sudo -n /usr/bin/labyrinth-agent-rec -- CMD...`
#     (privileged, but as the agent, and recorded).
# Run again on a system that has the account, it moves it to what is described here. --remove takes away the sudo rules,
# claude-sudo and the audit rule (auditd stays on); the accounts stay.
# The agent is never exempt from Heimdall's content checks (prompt injection, credentials, hidden characters).

labyrinth-rea [OPTIONS] REA-ARGUMENTS...: REA (reverse engineering for AI agents) inside a sandbox, for analysing files that may be hostile.

  labyrinth-rea decompile /samples/driver.sys ...   any REA command; `labyrinth-rea mcp` is the MCP server (for Sarina)
  --samples DIR   files to analyse, seen read-only as /samples   (default ~/Documents/Samples; created if missing)
  --work DIR      the only writable place (REA's results, Ghidra's cache), seen as /work   (default ~/.local/share/labyrinth/rea-work)
  --exec CMD...   run CMD in the sandbox instead of REA (to look around when something fails)
  --net           allow network (off by default; REA's browser and Android features need it, analysing a file does not)
Also visible read-only as /quarantine: the malware scan's quarantine (~/.local/share/labyrinth/quarantine/*/payload), so what Heimdall caught can be examined in place.

What the sandbox is (bubblewrap): no network, no access to your home, your files or the desktop, a private /tmp, read-only system, and it dies with its parent. What it is not:
a virtual machine. REA's runtime features (running a program under a debugger) would run the sample on this kernel in that sandbox: for samples that might attack the kernel use
Limbo (a disposable guest). Set up with labyrinth-rea-setup (REA, Ghidra) and a JDK 21.
